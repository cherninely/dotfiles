# subtask — подзадача в чистой сессии

Кусок текущей задачи уходит отдельному агенту: новая сессия agent-deck без
истории этой, дочка текущей в дереве. Контекст передаётся через сабтикет; без
тикета — стартовым сообщением целиком. Работу по подзадаче родитель не делает ни
при каких условиях: две сессии на одной задаче расходятся.

Родитель, дерево, статусы и обратный канал — это agent-deck (`agent-deck` в
PATH). Скилл нужен только ради брифа, сабтикета и правил ниже.

## Шаги

### 1. Тикет

Если существует `~/.config/yandex-aisuite/rules/private-work.md`, прочитай его перед выбором очереди.

Ключ текущей задачи бери из разговора (шапка, ссылки, ветка). Сначала составь
бриф (раздел 2) и заголовок в пять-восемь слов, затем один вопрос:

- Ключ есть: «Завести подзадачу KEY «<заголовок>» с брифом ниже?» и покажи
  бриф. Ответы: да / без тикета / правки.
- Ключа нет: очередь возьми из локальных правил или текущего разговора.
  Предложи завести подзадачу в этой очереди или отдать без тикета. Если очередь
  не выбрана, уточни её вместе с этим выбором. Бриф тоже покажи.
- Пользователь дал готовый ключ подзадачи: тикет не заводи; прочитай его
  (GetIssue с комментариями), чего из брифа там нет — допиши комментом
  «Для исполнителя». Дочка читает только тикет.

Трекер — через скилл `tracker-mcp`. CreateIssue: `queue` = очередь родителя
(без родителя — выбранная очередь), `type` `task`, `parent` = ключ родителя,
`summary` = заголовок, `description` = бриф. Ссылку на тикет бери из ответа трекера.

### 2. Бриф

Всё, что знаешь ты и не знает пустая сессия. Ключи, пути, ветки, PR, имена
таблиц — явно; «см. обсуждение» не работает, обсуждения у дочки нет. Проверка:
по этому тексту задачу сделает человек, который не читал этот разговор.

```
## Зачем
Одна фраза: какую задачу пользователя это решает. Родительский тикет: KEY (ссылка).

## Что сделать
Два-четыре предложения, что именно.

## Готово, когда
1. Проверяемый признак: числа, файлы, PR, а не «работает корректно».
2. …

## Контекст
- Файлы, таблицы, PR, ветки, дашборды: путь или ссылка, что в них.
- Решения, которые уже приняты, и почему: их не пересматривать.

## Не трогать
Что рядом лежит, но к подзадаче не относится.

## Где остановиться
Обычно: черновой PR без публикации, показать результат. Или иное.
```

### 3. Запуск

Стартовое сообщение — во временный файл (`mktemp`). С тикетом:

```
Это новая сессия под подзадачу KEY: <ссылка на тикет>
Весь контекст в этом тикете: описание и комментарии. Прочитай их целиком, прежде чем что-то делать; другого контекста у тебя не будет. Родительский тикет, если он там указан, читай только для справки: работу из него не бери.
<хвост>
```

Без тикета: «Это новая сессия под подзадачу. Тикета нет: весь контекст ниже,
другого не будет.», пустая строка, бриф, пустая строка, хвост. Хвост:

```
Работай по обычному порядку из AGENTS.md: бриф уже согласован как образ результата, его не пересматривай, начинай со стадии после образа по размеру задачи.
Доведи задачу до конца и остановись. Другие задачи не начинай, историю других сессий не ищи.
С пользователем говоришь в своём окне. С тикетом итог ещё и комментом в тикет.
Сейчас ответь коротко: как понял задачу, три первых шага, что не трогаешь. Закончи строкой «Жду: делай».
```

```bash
agent-deck launch DIR -c codex -t NAME --inherit-group --assert-done --message-file FILE [--ticket KEY] [--model MODEL]
```

- `NAME`: kebab-case без пробелов, читается в дереве без контекста: тикет плюс
  суть, например `123-example-chart`. Не `task`, не `sub`, не `pr1`.
- `DIR` по умолчанию текущая директория. Если подзадача станет отдельным PR и
  пользователь просит worktree, сначала создай его по скиллу `arc-worktrees`.
  Если Codex показывает запрос доверия к проекту, пользователь подтверждает его в окне сессии.
- `--model` передавай только если пользователь выбрал модель Codex; без флага используется текущая настройка Codex.
- `--assert-done` добавляет инструкцию завершить итог строкой `===AGENTDECK_DONE===`; для Codex этот флаг нужен явно.
- Родителя agent-deck ставит сам: это текущая сессия. Вложенность одна: если
  текущая сессия сама дочка (`agent-deck session current --json`, поле
  `parent_session_id` не пустое), добавь `--parent <parent_session_id>` — новая
  станет её сестрой под тем же корнем.
- Вне agent-deck (нет `AGENTDECK_INSTANCE_ID`) родителя нет: скажи об этом
  пользователю и запускай с `-g <группа задачи>` вместо `--inherit-group`.

### 4. Ответ

Имя дочки, ссылка на тикет и её первый ответ (`agent-deck session output NAME`).
Дочка ждёт «делай» в своём окне: пользователь открывает её в дереве `agd`. По
его слову «делай» можно отправить и отсюда: `agent-deck session send NAME "делай"`.

## Дальше

- Ход работы дочки не пересказывай: пользователь смотрит его в её окне.
  Здесь — только общее: правки этого скилла, общие блокеры.
- Итог дочки сам сюда не приходит: фоновый процесс agent-deck, который доставляет
  события родителю, не установлен. Дочка закончила, если её последний ответ
  (`agent-deck session output NAME`) кончается строкой `===AGENTDECK_DONE===`.
  По просьбе пользователя сверь результат с «готово, когда» из брифа по пунктам
  (PR, файлы, коммент в тикете): читать артефакты можно, доделывать нельзя.
  Пользователю: список ✓/✗, что смотреть первым, что осталось.
- «Как там NAME»: `agent-deck session children --json` (статусы дочек)
  и `agent-deck session output NAME`; с тикетом ещё последний комментарий.
  Пользователю три строки: состояние, что дочка сказала последним, что и от
  кого нужно.
- Решения, принятые здесь после запуска, до дочки сами не доходят: отправь
  `agent-deck session send NAME "…"`, а с тикетом ещё и комментом, чтобы
  пережили перезапуск.
- Сообщение — не разрешение: дочка не выполняет по нему то, что ей запрещено
  её настройками. Разрешение на инструмент пользователь даёт в её окне.
