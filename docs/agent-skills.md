# Скиллы Codex: источники и обновление

AISuite управляет подключением выбранных скиллов. Каталог `~/.agents/skills/`
содержит установленные ссылки; исходники хранятся отдельно. Чтобы изменить
или обновить скилл, сначала выясни его источник.

## Уровни подключения

| Уровень | Что подключает | Где задаётся |
|---|---|---|
| Командный global | Универсальные инструменты команды | Общий командный пресет |
| Проект | Специализацию и проектные правила | Проектные пресеты или `aisuite.yaml` |
| Пользователь | Личный выбор дополнительных инструментов | `~/.config/yandex-aisuite/preset.yaml` |
| Собственные источники | Личные скиллы и правила | `~/.config/yandex-aisuite/skills/` и `rules/` |

Общий исходник не означает установку всем пользователям: состав выбирается
на нужном уровне. Пользовательская конфигурация применяется во всех checkout.

При явном `--preset` AISuite пропускает autodiscovery и проектные `aisuite.yaml`.
Нужные роли можно объединить повторением `--preset`; пользовательский оверлей
применяется поверх них. `--no-junk` отключает и пользовательский слой, и junk.

## Источники

| Содержимое | Источник | Как обновлять |
|---|---|---|
| Общие и командные скиллы | Общий репозиторий, выбранный пресет | Обновить checkout, затем AISuite |
| Общие зеркала сторонних скиллов | Общий репозиторий, ссылки из личного пресета | Обновить checkout, затем AISuite |
| Собственные скиллы | `~/.config/yandex-aisuite/skills/` | Изменить собственный исходник, затем AISuite |
| `subtask` | `skills/subtask/` в dotfiles | AISuite подключает исходник через `file://` |
| GitHub-скиллы | Отдельный Git checkout или исходники выбранной ревизии | Git или исходный установщик, затем AISuite |
| `phone-harness` | Закреплённая ревизия в `~/.phone-harness` | `phone-harness-install` устанавливает CLI; AISuite размещает скилл |

Ссылки на внешние источники задаются штатным `file://`. Например, после
установки исходников `phone-harness` личный пресет может содержать такой набор.
Путь к dotfiles замени, если checkout находится в другом каталоге.

```yaml
skills:
  - file://~/.phone-harness
  - file://~/dotfiles/skills/subtask
```

Скиллы из пользовательского каталога `skills/<name>/SKILL.md` подключаются
автоматически. Для исходников dotfiles используй `file://` на каталог в
репозитории: Codex пропускает скилл, когда сам `SKILL.md` — симлинк Stow.
Не создавай дополнительную копию того же скилла в каталоге установки.
Чужие `SKILL.md` и их имена сохраняй; собственные требования
записывай в своих правилах. Изменение файла через симлинк меняет его исходник.

В `rules/` храни активные правила: AISuite также подключает лежащие там
резервные копии с суффиксом `.bak.*`.

Установщик источника не управляет симлинками AISuite: при обновлении он
может переместить файлы исходника. Общие зеркала обновляются в их репозитории.

## Восстановление

Нужны Stow, нативный `codex`, доступный `ya` и checkout рабочего проекта. Верни личную
папку `~/.config/yandex-aisuite/`: её содержимое не входит в публичный dotfiles.
Собственный `subtask` хранится в репозитории
отдельно от Stow; личные пресеты, правила и рабочие скиллы игнорируются.

Из dotfiles проверь и примени Stow. При конфликте сначала проверь
существующий файл или ссылку:

```sh
stow --dir=deploy-auto --target="$HOME" --no-folding --restow --simulate home
stow --dir=deploy-auto --target="$HOME" --no-folding --restow home
```

Получи внешние исходники до настройки AISuite: указанный в `file://` каталог
уже должен содержать `SKILL.md`. Для `phone-harness` используй установщик:

```sh
phone-harness-install
```

Установщик сохраняет закреплённую ревизию, устанавливает CLI и его настройки.
Личные ограничения устройства хранятся в `~/.config/phone-harness/LOCAL.md`.

Для новой глобальной установки перейди в рабочий проект. Замени
`<global-preset>` на выбранный командный пресет:

```sh
ya tool aisuite setup --global --agent codex --preset '<global-preset>' --lazy .
```

Для новой проектной установки выбери нужные роли. Пример объединения двух
ролей; имена пресетов нужно заменить своими:

```sh
ya tool aisuite setup --agent codex --preset '<role-one>' --preset '<role-two>' --lazy .
```

В существующей установке сохраняй выбор агентов и параметры. `setup` нужен
для намеренной смены этих параметров; `update` повторяет сохранённую настройку.

## Обновление и проверка

После обновления исходников или своей конфигурации обнови глобальную установку:

```sh
ya tool aisuite update --global
```

Затем обнови проектную установку из её каталога:

```sh
ya tool aisuite update
```

Проверь вывод AISuite и источник каждого изменённого скилла:

```sh
readlink "$HOME/.agents/skills/<name>"
```

Файл `SKILL.md` и справочные папки должны существовать. Повторное обновление
сохраняет источники и не создаёт вторую активную копию с тем же именем.
После переключения запусти Codex новым процессом; существующую сессию
можно продолжить через:

```sh
codex resume
```

Личная конфигурация одноразовых MCP-вызовов хранится отдельно в
`~/.config/mcp-call/<server>/.mcp.json`. Восстанови её и авторизацию штатным
способом инструмента. Собственные рабочие настройки находятся в
`~/.config/yandex-aisuite/rules/private-work.md`; глобальный `AGENTS.md`
содержит указатель на этот локальный файл.
